### Putaran 4 (audit lanjutan 2026-10-20, skor 96 -> putaran ini)
- **Idempotency terikat pemanggil** (migrasi `004-idempotency-principal.sql`): lookup replay putaran 3 hanya memakai `idempotency_key`, sehingga pemanggil B yang memakai key yang sama menerima respons pemanggil A. Kini ingress menurunkan **principal** dari kredensial pemanggil (SHA-256 header `Authorization`; tanpa kredensial: penanda eksplisit `anon` — yang disimpan selalu hash, bukan kredensial mentah) dan **fingerprint** request (method + path + SHA-256 body mentah); keduanya disimpan saat enqueue dan disalin atomik `respond.js` ke baris respons. Replay hanya cocok bila key + principal + fingerprint semuanya sama — principal beda diproses sebagai request baru (respons orang lain tidak bocor), key+principal sama tapi payload beda ditolak **409 Conflict**. Index unik parsial menjadi gabungan (key, principal) di kedua tabel; baris pra-migrasi (principal NULL) tidak pernah ter-replay. Tes baru di `tests/tunnel.test.mjs`: replay pemanggil sama, principal beda (saat antre & setelah pengiriman), 409 payload beda, dan migrasi 004.
- **Watchdog: deployment publik tanpa `.health-key` = GAGAL, bukan diam-diam sehat** (Gap D): bila `.tunnel-url` ada tapi `.health-key` hilang/kosong, `watchdog.sh` kini menulis baris `ERROR` keras ke `watchdog.log` setiap run (menyebut file yang hilang + akibatnya: probe kesehatan nonaktif, tunnel dinyatakan tidak sehat secara konfigurasi) — selaras dengan peringatan `doctor.sh`. Restart untuk proses yang benar-benar mati tidak terpengaruh. Tes watchdog menambah skenario file hilang, file kosong, dan kombinasi proses mati.
- **Instalasi bersih tidak lagi macet di boot 9Router** (Gap E): `scripts/setup-tunnel.sh` kini memprovision `.dashboard-pw` (generate acak, chmod 600, tidak menimpa yang sudah berisi; file kosong di-generate ulang) — file yang disyaratkan `start-9router.sh` sejak fail-closed putaran 3 tapi tidak pernah dibuat setup. `start-9router.sh` juga kini menolak `.dashboard-pw` KOSONG (bukan cuma tidak ada). Dites oleh `tests/setup-tunnel.test.sh` baru (wrangler stub, kini juga di CI) dan skenario fail-closed baru di `tests/launcher-smoke.sh`.
- **Upgrade**: README (en/id/ms) kini memerintahkan migrasi BERURUTAN 001 -> 002 -> 003 -> 004; `scripts/setup-tunnel.sh` menerapkannya otomatis; `scripts/check-tunnel-schema.sh` memverifikasi kolom migrasi 004.
- Suite: 31 tes Node + launcher smoke + watchdog (12 pemeriksaan) + installer + schema-check + setup-tunnel + doctor 14/14 + i18n 73 kunci — semua lulus lokal.

### Putaran 3 (audit lanjutan 2026-10-20, skor 89 -> putaran ini)
- **Batas payload = kapasitas D1 yang sebenarnya**: D1 membatasi satu string/BLOB/baris pada 2.000.000 byte, sedangkan body disimpan Base64 (mengembang 4/3) — batas lama (request 6 MiB, respons client 32 MiB) tidak pernah muat dan insert-nya akan gagal. Kini: body request maks 1.350.000 byte mentah (Base64 tepat 1.800.000 karakter), JSON header maks 32.768 byte, ditegakkan di ingress (413), di respond (413), dan di client (clamp `TUNNEL_MAX_RESPONSE_MB`). Tes batas persis di `tests/tunnel.test.mjs` + bukti di D1 asli (migrasi & tabel scratch) di `docs/validation/2026-10-20-round3-staging.md`.
- **Idempotency bertahan setelah pengiriman** (migrasi `003-response-idempotency.sql`): `respond.js` menyalin `idempotency_key` dari baris request ke baris respons dalam statement atomik yang sama; ingress melayani kiriman ulang langsung dari baris respons. Masa simpan pemetaan key -> respons default 24 jam (`IDEMPOTENCY_TTL_MS`), respons biasa tetap 120 dtk. Dulu baris request dihapus saat pengiriman pertama dan retry sesudahnya membuat request baru (efek samping ganda).
- **Lease tidak lagi balapan dengan kerja backend**: endpoint baru `__tunnel/heartbeat` — client memperpanjang klaimnya tiap 10 dtk (`TUNNEL_HEARTBEAT_MS`) selama backend bekerja; lease server 45 dtk kini murni batas mati (klaim direbut hanya bila perpanjangan berhenti). Tes: backend lambat 1,2 dtk + heartbeat terverifikasi di `tests/client.test.mjs`, klaim yang diperpanjang tidak direbut poller lain di `tests/tunnel.test.mjs`.
- **Probe kesehatan terautentikasi ujung-ke-ujung**: `GET /__tunnel-health` (secret `HEALTH_KEY`, header `x-tunnel-health-key`, timing-safe) masuk antrean tunnel seperti request biasa dan dijawab client dengan nonce + status backend. `watchdog.sh` dan `scripts/doctor.sh` kini memakai probe ini; kode 401/403 dari edge TIDAK lagi dianggap sehat (gate bisa menjawab sebelum request masuk antrean — false-healthy putaran 2). `scripts/setup-tunnel.sh` membuat `.health-key` + memasang secret-nya otomatis.
- **Upgrade & fail-closed deployment**: README (en/id/ms) kini memerintahkan migrasi BERURUTAN 001 -> 002 -> 003; `scripts/setup-tunnel.sh` menerapkannya otomatis pada database lama, membuat password gate dashboard + memasang `GATE_PASSWORD`/`REQUIRE_GATE=1` sebagai Pages secret secara default (opt-out `SETUP_NO_GATE=1` dengan peringatan), dan `start-9router.sh` kini MENOLAK jalan (exit 1) bila tunnel publik terkonfigurasi tapi `.dashboard-pw` tidak ada — bukan lagi sekadar peringatan. Preflight baru `scripts/check-tunnel-schema.sh` memverifikasi kelengkapan skema D1 dan mencetak perintah perbaikan persis; dites `tests/schema-check.test.sh` dan kini bagian dari CI.
- **Observability**: setiap respons ingress membawa `x-tunnel-request-id` (termasuk sukses, bukan hanya 504) dan ingress menulis log terstruktur JSON satu baris per request (selesai/timeout/replay).
- Suite: 26 tes Node + launcher smoke + watchdog (9 skenario) + installer + schema-check + doctor 14/14 + i18n 72 kunci — semua lulus lokal dan di CI.

### Putaran 2 (audit lanjutan 2026-10-20, skor 61 -> 78 -> putaran ini)
- **Release blocker P0 ditutup**: semua script entry-point kini tersimpan executable (100755) di git — clone segar di Linux tidak lagi gagal "Permission denied" saat `start-gateway.sh` memanggil `./run-hermes.sh`. `tests/launcher-smoke.sh` membuktikannya dari checkout apa adanya. CI `tunnel-tests` kini jalan di SEMUA branch push + PR (sebelumnya hanya `main`, branch rilis tidak pernah ter-CI), ditambah langkah smoke launcher, tes watchdog, dan tes installer.
- **respond atomik**: validasi klaim + tulis respons = satu statement `INSERT ... SELECT ... WHERE EXISTS` (menutup jendela race SELECT->INSERT putaran 1). Lease klaim 30 dtk kini lebih pendek dari masa tunggu ingress 40 dtk; timeout ingress TIDAK membatalkan request — pemanggil menerima 504 + `x-tunnel-request-id` dan hasil akhir diambil via `GET /__tunnel/result?id=...`.
- **Idempotency & proteksi publik**: header `idempotency-key` mencegah request ganda berside-effect (migrasi 002: kolom + index unik parsial); rate limit per IP di ingress (default 120/menit, `RATE_LIMIT_PER_MIN`); gate HTTP Basic opsional untuk dashboard (`GATE_PASSWORD`/`GATE_USER`, `REQUIRE_GATE=1` tanpa password = 500 fail-closed); body ingress kini dibaca streaming berbatas (jalur tanpa Content-Length tidak lagi ditampung utuh di memori).
- **Installer menegakkan pin versi**: versi terpasang 9Router & Wrangler diverifikasi terhadap pin (package.json) — beda versi dipasang ulang persis pin (upgrade/downgrade), hasil akhir dicek ulang, tak cocok = gagal jelas. Dites oleh `tests/installer-version.test.sh` (mengekstrak fungsi asli installer).
- **Watchdog**: kunci `flock` anti-run-tumpang-tindih + cek ujung-ke-ujung URL publik (`.tunnel-url`) untuk client hidup-tapi-macet. Dites oleh `tests/watchdog.test.sh` (6 skenario).
- **Tes client sungguhan** `tests/client.test.mjs`: client dijalankan sebagai proses melawan server stub — redirect backend terbukti TIDAK diikuti, timeout backend -> 502, respons normal utuh. Total suite: 18 tes Node + 3 tes shell, semua lulus; i18n 65/65 bersih di 3 bahasa.

### Keamanan (audit menyeluruh 2026-10-20)
- **Tunnel auth FAIL-CLOSED** (`functions/__tunnel/poll.js`, `respond.js`): `TUNNEL_KEY` yang tidak ter-set di server kini menolak SEMUA request. Sebelumnya cek `key !== env.TUNNEL_KEY` lolos bila key request dan secret server sama-sama kosong — tunnel tanpa secret berarti terbuka.
- **Klaim antrean ATOMIK + lease** (`poll.js`, `schema.sql`, `migrations/001-claim-lease.sql`): klaim kini satu statement `UPDATE ... RETURNING` dengan `claim_token` + `claimed_at`. Menghilangkan race double-processing (dua poller menerima request yang sama) dan request yatim (klaim basi >45 dtk direbut kembali ke pending). `respond.js` hanya menerima respons dari pemegang klaim yang sah (token cocok), selain itu 409.
- **tunnel-client.mjs**: redirect backend tidak lagi diikuti (`redirect: "manual"` — respons 3xx diteruskan apa adanya, menutup jalur belok ke port/host lain); semua fetch ber-timeout eksplisit; respons backend dibaca streaming dengan batas 32 MB (dulu `arrayBuffer()` tanpa batas); `TUNNEL_LOCAL` wajib loopback kecuali opt-in `TUNNEL_ALLOW_REMOTE_LOCAL=1`; body request di ingress dibatasi 6 MB (lebih dari itu 413).
- **Test suite tunnel** (`tests/`, workflow CI `tunnel-tests.yml`): fungsi Pages ASLI dijalankan melawan SQLite sungguhan — regresi fail-closed, klaim atomik dua poller, lease/reclaim, round trip penuh, dan batas body. Plus cek sintaks shell & kelengkapan i18n di CI yang sama.
- `AGENTS.md`: token bot Telegram sebaiknya dimasukkan user langsung ke `.env` lokal, bukan lewat chat; bila terpaksa lewat chat, tulis segera dan jangan pernah di-echo.
