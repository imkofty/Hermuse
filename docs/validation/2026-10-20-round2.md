## 2. Migrasi + smoke di D1 Cloudflare SUNGGUHAN

Database: `tunnel-9router` (database tunnel Hermuse sendiri, dibuat
2026-09-27) di akun Cloudflare yang sama, diakses via Cloudflare REST API.
Kondisi awal: skema ASLI (7 kolom, tanpa kolom klaim) dengan **2.997 baris**
antrean lama — kasus migrasi produksi yang sebenarnya. Database ini juga
memuat tabel `cockpit_*` milik MuseCockpit; tabel itu TIDAK disentuh.

- Migrasi `001-claim-lease.sql` + `002-idempotency-ratelimit.sql`:
  6 statement, semua sukses.
- Kolom sesudah migrasi: `id, method, path, headers, body, status,
  created_at, claim_token, claimed_at, idempotency_key`.
- Jumlah baris `tunnel_requests`: **2.997 sebelum = 2.997 sesudah**
  migrasi maupun sesudah cleanup pengujian (data lama utuh).
- Smoke terisolasi (baris `val-r2-*`, dibersihkan sesudahnya):
  - INSERT request dengan idempotency key: sukses.
  - INSERT kedua dengan idempotency key yang sama: **ditolak** (index unik).
  - Klaim atomik `UPDATE ... RETURNING` (SQL yang sama dengan poll.js): 1 baris.
  - Respond token salah (statement atomik respond.js): changes = 0.
  - Respond token benar: changes = 1.
  - Rate limit upsert 2x untuk IP yang sama: count = 2.

Catatan: akun Cloudflare sudah mencapai batas 10 database D1, jadi
database validasi terpisah tidak bisa dibuat — validasi memakai database
tunnel yang memang milik proyek ini (stack sedang nonaktif; tidak ada
lalu lintas langsung yang terganggu, dan migrasi bersifat aditif).
